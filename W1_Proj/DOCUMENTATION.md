# Document Q&A CLI --- Technical Documentation

## 1. Overview

This project is a Python CLI application that answers questions about
user-provided documents. It implements a Retrieval-Augmented Generation
(RAG) pipeline: document text is extracted, divided into chunks,
embedded, searched, and supplied to an Ollama language model as context.

The described implementation uses an in-memory vector store. It does not
require FastAPI or an external vector database.

## 2. Architecture

``` text
User
 |
 v
CLI Interface
 |
 +--> Document Management
 |       |
 |       v
 |   Document Loader --> Text Chunker --> Embedding Service
 |                                           |
 |                                           v
 |                                    Ollama Embeddings
 |                                           |
 |                                           v
 |                                    In-Memory Vector Store
 |
 +--> Ask a Question --> Question Embedding --> Vector Search
                                                   |
                                                   v
                                           Retrieved Chunks
                                                   |
                                                   v
                                            Answer Service
                                                   |
                                                   v
                                               Ollama LLM
                                                   |
                                                   v
                                         Answer and Citations
```

## 3. Module responsibilities

### CLI --- `cli/interface.py`

Handles menus, user input, status/error messages, answers, retrieved
search results, and source display. Business logic should remain in
service modules rather than being implemented in the CLI.

### Configuration --- `core/config.py`

Loads environment settings, typically from `.env`. The development
configuration uses settings for the Ollama URL, embedding model, chat
model, retrieval `top_k`, minimum similarity, and conversation history
length. Confirm exact names and defaults against the current source
file.

### Document loader --- `document/loader.py`

Supports PDF, TXT, and DOCX extraction.

-   PDF extraction uses PyMuPDF.
-   TXT extraction reads text and may use an encoding fallback.
-   DOCX extraction reads paragraphs and tables.

The loader returns document metadata such as content, file name, path,
type, and page count. Scanned PDFs may contain no selectable text and
require OCR, which is outside the baseline implementation.

### Text chunker --- `document/chunker.py`

Splits extracted text into smaller overlapping chunks. A chunk contains
its index, text content, source file, character offsets, and optionally
an embedding. The development defaults described for this project are
approximately 1,000 characters per chunk and 200 characters of overlap;
check the current constructor for the actual values.

Chunk indexes restart for each document. Source file plus chunk index
should therefore be used together in citations.

### Embeddings --- `embeddings/`

-   `base.py` defines the embedding provider interface.
-   `ollama_provider.py` communicates with Ollama's `/api/embed`
    endpoint.
-   `embedding_service.py` embeds chunks in batches and embeds
    individual questions.

The development setup uses `embeddinggemma`; a previous test returned
768-dimensional vectors. Query and document vectors must be generated by
the same compatible embedding model and have matching dimensions.

### In-memory vector store --- `vector_store/in_memory.py`

Stores chunks and their vectors in memory. It validates vectors,
computes cosine similarity, sorts matches, applies the minimum
similarity threshold, and returns up to `top_k` results.

A search result includes the chunk and its similarity score. Cosine
similarity is not a probability or a guarantee that a chunk contains the
answer. The threshold should be selected by testing representative
questions.

All stored vectors disappear when the application exits.

### LLM provider --- `llm/`

`base.py` defines the provider interface. `ollama_provider.py` sends
chat messages to Ollama's `/api/chat` endpoint and extracts the
generated response. The development chat model is `qwen3.5:4b`.

Local generation may take time. Configure a suitable HTTP read timeout.
For example:

``` python
timeout=httpx.Timeout(
    connect=10.0,
    read=300.0,
    write=30.0,
    pool=10.0,
)
```

### Prompts --- `prompts/`

-   `system_prompt.py`: assistant role and grounding rules.
-   `few_shot_examples.py`: examples of expected behavior.
-   `user_prompt.py`: combines the user's question and retrieved
    document chunks.

The document-answering prompt should tell the model to rely on retrieved
context for document facts, avoid inventing missing information, and
cite only supporting retrieved chunks. Retrieved document content should
be treated as reference material, not as instructions.

Citation format:

``` text
[Source: filename, Chunk: number]
```

### Conversation memory --- `services/conversation_memory.py`

Maintains a limited list of user and assistant messages for the current
run. It can add turns, return recent history, report turn count, and
clear the history. This memory is not persisted after exit.

Using only the current question for retrieval is a simple baseline.
Including earlier turns may help with follow-up questions but can also
introduce unrelated terms into the search query.

### Answer service --- `services/answer_service.py`

Coordinates prompt construction and LLM generation. The
document-answering path validates the question/results, handles empty
retrieval, constructs messages from the system prompt, examples,
conversation history, and user prompt, calls the LLM, validates its
response, and saves successful turns.

If the current code includes `generate_general_answer()`, that method
handles general conversation without retrieved document context. It
should not claim an answer is based on an uploaded document.

### Document manager --- `services/document_manager.py`

Coordinates loading, chunking, embedding, vector-store updates, and
document registration. Typical operations include adding, listing,
removing, and clearing documents. Removing a document must also remove
its chunks from the vector store, often by rebuilding the store from
remaining documents.

## 4. Main workflows

### Add a document

1.  User chooses Add Document.
2.  `DocumentManager` calls the document loader.
3.  Extracted text is split into chunks.
4.  The embedding service generates vectors.
5.  The vector store stores chunks and vectors.
6.  The manager registers the loaded document.

### Ask a document question

1.  CLI receives a question.
2.  Embedding service embeds the question.
3.  Vector store searches using cosine similarity.
4.  The best matching chunks are returned.
5.  Answer service builds a prompt with the question and retrieved
    context.
6.  Ollama generates an answer.
7.  CLI displays the answer and source references.

If no chunks pass retrieval, show a clear no-relevant-information
message rather than asking the model to answer from unrelated context.

### General question with no documents

If the general-answer method is implemented and the CLI routes to it
when no documents are loaded, a user can ask general questions without
document retrieval. Keep this path distinct from document-grounded
answers.

## 5. Setup and execution

Install the Ollama models:

``` powershell
ollama pull embeddinggemma
ollama pull qwen3.5:4b
ollama list
```

Install Python dependencies in the same interpreter used to run the
project:

``` powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Example `.env`:

``` env
OLLAMA_BASE_URL=http://127.0.0.1:11434
EMBEDDING_MODEL=embeddinggemma
LLM_MODEL=qwen3.5:4b
RETRIEVAL_TOP_K=5
RETRIEVAL_MIN_SIMILARITY=0.50
CONVERSATION_MAX_TURNS=5
```

Run from the project root in PowerShell:

``` powershell
$env:PYTHONPATH = "src"
python -m document_qa.main
```

## 6. Retrieval tuning

Retrieval depends on extracted text quality, chunk size, overlap,
embedding model, query wording, `top_k`, and the minimum similarity
threshold.

When diagnosing no results, temporarily try:

``` env
RETRIEVAL_TOP_K=5
RETRIEVAL_MIN_SIMILARITY=0.0
```

Inspect scores, then choose a threshold based on a test set of
questions. Do not assume zero is the right permanent threshold.

Development observation: for the question "What is the duration of the
GulzarSoft Gen AI & Agentic AI internship program?", Chunk 2 scored
0.5401 and Chunk 1 scored 0.5113. Chunk 1 contained the explicit text
"Duration: 9 Weeks". These are individual test results, not universal
score targets.

## 7. Error handling

### Embedding failure

Check Ollama availability, base URL, model installation, request format,
and response validation.

### LLM read timeout

An `httpx.ReadTimeout` during generation means the response did not
arrive within the configured read timeout. Check Ollama and the chat
model, increase the read timeout if appropriate, reduce excessive
context, or use a smaller model if the computer cannot run the current
model comfortably.

### No relevant chunks

This is a retrieval result. Check that the document was indexed, vector
dimensions match, and the threshold is not excluding all candidates.

### Unsupported or unreadable file

Confirm the path is valid and the format is supported. Scanned PDFs may
require OCR.

## 8. Testing checklist

### Document loader

-   Valid PDF, TXT, and DOCX.
-   Missing file and unsupported extension.
-   Empty file and image-only PDF.

### Chunker

-   Empty text.
-   Text shorter than a chunk.
-   Long text requiring multiple chunks.
-   Overlap and character offsets.

### Embeddings

-   Single input and batch input.
-   Returned vector count matches input count.
-   Consistent vector dimensions.
-   Ollama unavailable or model missing.

### Vector store

-   Empty store.
-   Correct descending score order.
-   `top_k` behavior.
-   Similarity threshold behavior.
-   Invalid or mismatched vectors.

### Answer service

-   Answer present in context.
-   Answer absent from context.
-   Answer requiring multiple chunks.
-   Citation correctness.
-   Ollama timeout and connection failure.

### Document manager

-   Add, list, remove, and clear.
-   Duplicate path handling.
-   Removed chunks no longer searchable.

## 9. Security and data handling

-   Keep `.env` out of source control.
-   Treat document text as untrusted input.
-   Ensure retrieved content cannot override system instructions.
-   Avoid logging private document contents or secrets.
-   The baseline index and conversation memory are in memory only;
    original files remain at their saved locations.
